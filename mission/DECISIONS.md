# DECISIONS — key autonomous calls (append-only)

- **D1 — Build the game's own V1, not a divergent design.** Docs specify a full 3-region V1 only ~1/3 built; the mission target == that V1. Extend the existing data-driven systems; don't invent parallel ones. Use the project's canon names (Borderlands/Elderwood/Shattered Reach, enemy families, material tiers) — original to the project, Caelmor-safe.
- **D2 — Region I deep-first.** Build "The Borderlands" into a complete, fun open-world vertical (Adventurer→Vanguard) before touching Regions II/III. Depth of one coherent region > shallow skim of three.
- **D3 — Mission branch `feature/open-world-rpg` off `feature/living-world-enemies`.** Includes the living-world enemies. Final mission draft PR supersedes PR #33 (close #33 in favor of it, or note its commits are ancestors).
- **D4 — World executor: keep server-side kinematic-CFrame enemy movement** (from living-world work) even on terrain, provided territories sit on walkable ground; revisit Pathfinding only if terrain elevation breaks straight-line movement. Enemy movement stays behind the executor-agnostic `EnemyAI` intent layer.
- **D5 — World is Studio-owned but reproducibly built.** Author a repository **scene-builder** module run edit-time via the MCP (terrain sculpt + tagged-marker placement) so the world is regenerable and reviewable, while the actual terrain/scene lives in the Studio place (saved by the owner). Repo owns the builder + all data; Studio owns the resulting scene.
- **D6 — Placeholders:** primitives + Roblox Terrain + (sparingly) Studio generative-mesh/material tools for a few hero props; enemy meshes reused; document replacement seams. No multi-day art polish.
- **D7 — Play SURFACE stays flat (for now); relief comes from scenery.** To keep the kinematic-CFrame enemies grounded (D4) without per-move raycasts, walkable zones are flat; verticality is delivered via terrain edge-hills, a keep tower, rock spires, and tree canopy. If the Phase-2 evaluator still marks criterion 2 (distinct places) below 4, do a dedicated terrain-elevation pass — flat plateaus per zone at different heights joined by ramps, OR make enemies ground-aware (raycast Y) — rather than piecemeal.
- **D8 — Difficulty gradient via per-territory level bands** (`LevelMin/Max` marker attributes → `Enemies.Create` clamps into the archetype band), reused on respawn. This makes distance-from-town mean difficulty without new enemy archetypes, and composes with Phase-2 archetypes.
- **D9 — Evaluator cadence:** an independent evaluator grades each PHASE end (not every micro-fix). Within a phase, verify fixes objectively (tests + live playtest evidence). Keeps the critic loop honest without burning budget on redundant full reviews.

## Post-review reconciliation (external review + terrain reassessment)

- **D10 — Terrain elevation pass, SUPERSEDES D7's flat-surface constraint.** The final evaluation graded world/exploration below threshold and treated the flat plane as an accepted tradeoff; D7 itself named the escalation ("make enemies ground-aware (raycast Y)" and/or a real elevation pass). Executed BOTH: (a) `World/Service.luau` enemies now terrain-follow via a per-move downward `workspace:Raycast` against Terrain (`sampleGroundY`), rejecting ledges/water/over-steep steps so roaming avoids hazards without a pathfinding graph; on flat ground it is a no-op. (b) `studio/RegionOneBuilder.luau` rebuilds the flat plane into a height field — a flat town basin (existing hub parts/spawn stay seated) rising into rolling wilderness, the mine hollow dipping below town. Verified live in Studio: gentle walkable slopes (0.04–0.14), enemies track the surface within ~0.1–0.3 studs while chasing, clean boot. This annotates **D4**: kinematic-CFrame movement is KEPT; grounding is now raycast-per-move (bounded by the sleep gate) rather than a fixed spawn height — Humanoids handle player slope-walking natively.
- **D11 — Region I stays "The Borderlands" (reconcile an unauthorized rename).** The branch had drifted Region I to "The Marchlands" with no owner decision; DESIGN_SOURCE_OF_TRUTH / V1_SCOPE / DECISION_LOG and D1/D2 all say "The Borderlands." Reverted the id (`region_borderlands`) and all display strings. Zone names (Havenbrook, Whispering Woods, etc.) were valid and unchanged. Region ids are runtime-only (not persisted), so the rename carries no migration.
- **D12 — Mastery identities re-grounded in docs/MASTERY_TREES.md (not mechanical patches).** Merchant Smith bonus is scoped to goods the player FORGED (Smithing OutputItemIds), item-aware via `Economy.SaleValueBonusFromData(data, definitionId)` fed by a `forgedGoodIds` set in Composition — not a generic NPC-sale buff. Smelter is realized as `ProcessingEfficiencyBonus` reducing ore consumed when smelting ore→bars (there is no craft-duration to speed up), while Forgemaster keeps `MaterialEfficiencyBonus` for equipment; the unused `ProcessingSpeedBonus` effect is removed. Resilience `RecoveryBonus` regenerates only OUT OF COMBAT (a 5s last-damage gate in `PlayerHealth`, injectable clock), matching the "recovery without an active blocking scheme" identity. Cleave excludes bosses as splash targets and routes cleaved NORMAL-enemy deaths through the normal death/Gold flow (group farming), never the boss single-target/participation path.
- **D13 — Gathering context UI resolves the node by id.** The client contextual prompt looked up `GatheringNodes[1]`, valid only when one node type existed; now that Iron and Coal both exist, Controller passes `NearNodeId` and Interface resolves the matching node (falling back to the first only if unknown).
